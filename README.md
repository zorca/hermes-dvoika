# Двойка (dvoika) — Claude + DeepSeek

Скилл для Hermes: решение проходит через **две модели и три роли**. Claude Sonnet думает,
ставит ТЗ, собирает финал и отдельным прогоном критикует; DeepSeek Flash делает весь
объём. Платить за объём по дешёвому тарифу, а проверку получать отдельным контекстом,
а не самопохвалой внутри одного рассуждения.

| Роль | Модель | Что делает |
|---|---|---|
| Дирижёр (Conductor) | Claude Sonnet | цель, критерии, ТЗ работяге, финальная сборка |
| Работяга (Worker) | DeepSeek Flash | анализ, варианты, черновики, ресёрч, черновой код |
| Критик (Critic) | Claude Sonnet, **отдельный прогон** | ломает результат работяги, ранжирует дыры, проверяет инструментально |

## Установка

```bash
hermes skills install https://raw.githubusercontent.com/zorca/hermes-dvoika/main/skills/dvoika/SKILL.md -y
hermes skills check                                  # -> dvoika | skills.sh | up_to_date
```

Альтернатива, если репозиторий когда-нибудь снова станет приватным: `hermes skills tap add zorca/hermes-dvoika`, затем `hermes skills install zorca/hermes-dvoika/dvoika -y`.

Установлено и проверено 2026-10-08: файлы в `$HERMES_HOME/skills/dvoika/`, реестр знает
скилл (`created_by: installed`), сам скилл грузится (`readiness: available`). Учтите:
`hermes skills search` и `inspect` смотрят в хаб и этот скилл не находят; в таблице
`hermes skills list` он появится после первого реального использования.

Триггеры: `двойка`, `прогони через двойку`, `Claude + DeepSeek`, `совет`,
`red team this`, `через 2 модели`, `прокритикуй решение`.

## Что внутри

- `SKILL.md` — сам скилл: роли, восемь железных правил, процесс, механизмы запуска,
  питфоллы, форматы финала.
- `references/recipes.md` — конкретные команды: проверка пары, MoA-пресет, ручной прогон
  в три процесса, cron, установка.
- `references/projects.md` — таблица ваших проектов: чем критик обязан проверять
  (команды тестов, ограничения веток и стендов).

## Механизмы (что реально проверено)

```bash
hermes -z "…" -m deepseek-flash  --provider deepseek    # работяга
hermes -z "…" -m claude-sonnet-5 --provider anthropic   # дирижёр / критик
hermes moa configure && hermes moa list                 # пресет: references + агрегатор
```

Проверено 2026-10-08 на этой машине: `deepseek-flash` через `hermes -z … -m … --provider …`
отвечает (получено `ok`); механизм один и тот же для любой пары. Тогда же прогон с
`claude-sonnet-5` ушёл в таймаут, потому что креденшел Anthropic был в состоянии
`exhausted` — перед прогоном проверяйте `hermes auth status` и обновляйте креденшел
(`hermes auth add anthropic` / `hermes login`), иначе команда просто провисит до таймаута.

`-z` (`--oneshot`) принимает промпт **значением флага**; флаги подкоманды `chat`
(`-Q` и прочие) в этом режиме не работают. `delegate_task` сюда не подходит: дети
наследуют модель родителя, выбор модели возможен только глобально
(`delegation.provider` / `delegation.model` в `config.yaml`).

## Чем отличается от оригинала

Взята идея и структура ролей из [HinkoK/hermes-troitsa](https://github.com/HinkoK/hermes-troitsa) (MIT).
Отличия по существу:

1. **Пара вместо тройки** — Claude Sonnet + DeepSeek Flash; независимость даёт изоляция
   контекста, а не количество семей моделей.
2. **Прописаны реальные механизмы** запуска (MoA-пресет, одноразовые вызовы разных
   моделей, cron) вместо «вызывай, если доступно».
3. **Критик обязан опираться на артефакты** — файлы, тесты, логи, живые страницы; в
   финале указывается, чем проверено и что осталось гипотезой.
4. **Максимум один цикл правки** — против разрастания прогона.
5. **Объём уходит в файл**, критик получает путь и критерии, а не весь текст.
6. **Честность о вызовах** — нельзя называть модель, которая не вызывалась.
7. **Список проектов с командами проверки** — критик знает, что запускать в ваших репозиториях.
