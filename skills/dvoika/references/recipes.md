# Рецепты прогонов

Проверено на этой машине: одна сессия Hermes, путь к CLI —
`/c/Users/zorca/AppData/Local/hermes/hermes-agent/venv/Scripts/hermes`.

**Перед прогоном — проверить креденшелы.** Если статус модели `exhausted` (бывает у
Anthropic-пула), одноразовый вызов не падает с ошибкой, а висит до таймаута:

```bash
hermes auth status        # или hermes auth list
```

Обновление: `hermes auth add anthropic` либо `hermes login`.

## 0. Проверка, что пара действительно работает

```bash
# работяга
hermes -z "Ответь ровно одним словом: ok" -m deepseek-flash --provider deepseek
# дирижёр / критик
hermes -z "Ответь ровно одним словом: ok" -m claude-sonnet-5 --provider anthropic
```

Промпт передаётся **значением флага** `-z` (`--oneshot`). Флаги подкоманды `chat`
(`-Q`, `--quiet`, `--max-turns`) в этом режиме не принимаются: они работают только
как `hermes chat -q "…" -Q`. Факт проверки 2026-10-08: DeepSeek ответил `ok`;
Claude не ответил из-за `exhausted` креденшела (не из-за синтаксиса команды).

## 1. MoA-пресет (основной путь)

```bash
hermes moa configure     # интерактивно: reference-модели + агрегатор
hermes moa list          # слоты + предупреждение, на чьём провайдере биллится прогон
```

Дальше:

- разово: `/moa <задача>` — один ход через пресет, затем возврат на прежнюю модель;
- на сессию: `/model --provider moa` и выбрать пресет.

Приём с парой: агрегатор — Claude Sonnet (он думает, собирает финал и держит агентный
цикл), reference — DeepSeek (советует один раз за ход, объём отдаётся ему). Если хочется
настоящей третьей семьи для критики, добавьте reference другого провайдера из доступных
на машине (`hermes moa list` показывает текущий набор, в том числе gpt-5.5 через
`openai-codex`) — но это уже выход за рамки двойки, и в финале надо это отметить.

Важно про деньги: платит **агрегатор**, потому что он ведёт каждый шаг цикла. Строку с
провайдером агрегатора печатает `hermes moa list` — сверяйте её перед длинным прогоном.

## 2. Ручной прогон: роль = отдельный процесс (две модели, три прогона)

Так независимость настоящая: у работяги и критика разные процессы, разные контексты,
разные модели.

```bash
# 1) ТЗ и критерии пишем в файл-артефакт, а не в аргумент
#    artifacts/00-brief.md

# 2) работяга — объём
hermes -z "Прочитай C:/projects/.../artifacts/00-brief.md, сделай работу по нему и запиши результат в artifacts/10-worker.md. Верни только: путь к файлу + 5 строк сути." \
  -m deepseek-flash --provider deepseek

# 3) критик — другой процесс, другая модель, требует артефакты и инструменты
hermes -z "Ты критик. Задача в artifacts/00-brief.md, результат работяги в artifacts/10-worker.md.
Проверь его инструментально: прочитай файл, запусти команды проверки из references/projects.md.
Не переписывай результат. Ранжируй найденное: критично / средне / мелочь. Запиши в artifacts/20-critic.md." \
  -m claude-sonnet-5 --provider anthropic

# 4) финал — дирижёр сводит оба файла
hermes -z "Сведи artifacts/00-brief.md, artifacts/10-worker.md и artifacts/20-critic.md в финал по формату скилла dvoika: вывод, почему, риски, что проверено, что гипотеза, что дальше." \
  -m claude-sonnet-5 --provider anthropic
```

Артефакты — в каталоге задачи, а не в переписке: в промпт идёт путь, а не содержимое.
Иначе экономия на дешёвом работяге съедается контекстом критика.

## 3. Проверить, что модель реально вызывалась

```bash
hermes sessions list        # сессии одноразовых прогонов
hermes logs                 # журнал запусков
```

Если в отчёте названа модель, которой в списке нет, — выдумка. Требуйте артефакт.

## 4. Регулярный совет по расписанию

Через инструмент `cronjob` или CLI (`hermes cron create <расписание>`): в задаче указать
скилл `dvoika`, а при необходимости — свои `model` / `provider`. Расписание удобно
ставить на утро понедельника, чтобы разбирать недельные решения отдельным прогоном,
не занимая основную сессию.

## 5. Установка и проверка скилла

```bash
hermes skills install https://raw.githubusercontent.com/zorca/hermes-dvoika/main/skills/dvoika/SKILL.md -y
hermes skills check                                   # -> dvoika | skills.sh | up_to_date
```

Если репозиторий станет приватным, прямая ссылка перестанет работать (CLI не подставляет
токен) — тогда через tap: `hermes skills tap add zorca/hermes-dvoika` и
`hermes skills install zorca/hermes-dvoika/dvoika -y`.

Файлы лягут в `$HERMES_HOME/skills/dvoika/`. Что важно знать про проверки:
`hermes skills search` и `hermes skills inspect` смотрят в хаб и этот скилл не находят —
ориентируйтесь на `hermes skills check` и наличие файлов на диске. В таблице
`hermes skills list` скилл появится после первого реального использования
(до этого у него `first_seen_at: null`).
