# Проекты: чем критик обязан проверять

Правило скилла: критик не рассуждает, а проверяет. Для задач по коду и интерфейсам он
запускает соответствующую команду из таблицы и только после этого ставит «критично».

| Проект | Где | Обязательная проверка | Ограничения |
|---|---|---|---|
| noriukalbeti (школа, Laravel 13 + Botble, плагин school) | `C:\projects\noriukalbeti` | `~/.config/herd/bin/php84/php.exe artisan test` (php не в PATH; тестовая БД `noriukalbeti_testing` на Docker-контейнере `mysql-server`) | тесты обязательны до вердикта; вёрстку проверять в браузере |
| app (бот уроков литовского: Laravel 12 + Filament + Nutgram) | `C:\projects\app` | локальные тесты; деплой `php dep deploy production` (враппер `dep` — только через `php`) | прод-хост и путь пользователя — в `deploy.php`; расписание в `/etc/cron.d/noriukalbeti-app` |
| FluForm (api / bo / client) | `C:\projects\fluform-*` | тесты API (`artisan test`), проверка на дев-стенде проекта (адрес — в окружении) | **ветка `main` — основная, все PR только в `main`**; `dev` — только деплой (push в `dev` запускает `migrate:fresh` и стирает стенд). Выкат = продвинуть `main` в `dev` |
| virtuvespasaulis (Bedrock + WordPress) | `C:\projects\virtuvespasaulis` | браузерная проверка страниц; локально — сборка ассетов | плагины Composer тянутся из `local-packages/*.zip`; на проде доступа по SSH нет, только браузер/wp-admin; хост деплоя — в `deploy.php` |
| baraxolka-bot (Cloudflare Workers + D1 + KV) | `C:\projects\baraxolka-bot` | локально `npx wrangler dev --port 8787`, полная батарея `bash scripts/battery.sh` | бот платной модерации группы; проверять набор целиком, а не отдельный пункт |
| lt-news (пайплайн новостей Литвы) | `C:\projects\lt-news` | прогон скрипта на тестовом канале до публикации | рабочий канал задаётся `TG_CHANNEL` в `secrets.env`; бюджет подписи 1024 знака вместе со ссылками |
| lab плагинов WordPress | `C:\projects\wordpress` | активация плагина и проверка в браузере | **всё только на английском** (включая комментарии и интерфейс) |

Если проекта нет в таблице — критик сначала ищет команду проверки в `AGENTS.md` /
`CLAUDE.md` / `README.md` репозитория и **не** ставит вердикт без запуска.

Отдельно для непроектных решений (стратегия, цена, контент, планы запуска): обязательный
артефакт — документ с цифрами и допущениями (файл), а проверка — сверка цифр с источниками
(сайты, прайсы, статистика), а не повторное рассуждение.
